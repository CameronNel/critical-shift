# Critical Shift — Facility Greybox (Three.js prototype)

A browser-based **level-design prototype**. It exists to answer spatial
questions about the Critical Shift facility — room scale, routes, chokepoints,
sightlines, vertical relationships, machine footprints — from a phone or a
desktop browser.

**This is not production game code.** No networking, no physics engine, no
gameplay simulation, no Steam, no voice. It is deliberately isolated in
`prototype/threejs-facility/` so it can be removed by deleting this directory
plus `.github/workflows/prototype-pages.yml`, once the engine decision in
[`docs/ENGINE_DECISION.md`](../../docs/ENGINE_DECISION.md) is made and the real
facility is built in Unity or Godot.

The layout it describes is documented in
[`DESIGN_NOTES.md`](DESIGN_NOTES.md) — read that to understand *why* the
facility is shaped the way it is, and to say what you want changed.

## Run it

```bash
cd prototype/threejs-facility
npm install
npm run dev            # binds 0.0.0.0:5173 already
```

Open `http://<your-machine-ip>:5173` on a phone on the same network.

```bash
npm run build          # typecheck + production bundle into dist/
npm run build:single   # one self-contained HTML file in dist-single/
npm run preview        # serve the production bundle on 0.0.0.0:4173
npm run validate       # headless structural check of the facility document
npm run check          # typecheck + validate + build
```

`npm run build:single` produces `dist-single/critical-shift-greybox.html`: the
entire prototype in one file with no external requests. Mail it to yourself,
drop it in cloud storage, open it from anywhere.

## Controls

| | Phone | Desktop |
|---|---|---|
| Move | Left thumb anywhere on the left of the screen | `WASD` |
| Look | Right thumb drag | Mouse (click to lock) |
| Sprint | `Sprint` button | `Ctrl`, `Shift` or `Q` |
| Height (fly/map) | `▲` `▼` buttons | `Space` / `Shift`, wheel in map |
| Mode | `Walk` `Fly` `Map` `Edit` buttons | `F` fly, `M` map, `E` edit |
| Reset | `Reset` button | `R` |
| Menu | `☰` | `☰`, `Esc` closes |

## Modes

- **Walk** — 1.75 m worker at eye height, gravity, step-up, collision. The mode
  that answers "how far is that, really".
- **Fly** — no collision. Roofs, spans, vertical relationships, boundaries.
- **Map** — high-angle site view with a zone legend. Roofs drop automatically.
  Tap a zone in the legend to fly the map to it.
- **Edit** — tap an object to select it, then nudge, rotate, scale, duplicate,
  delete or type exact numbers. Press-and-drag still looks around.

## Menu

- **Layers** — hide roofs to read the plan, hide the ground to inspect the mine,
  the crusher pit and the maintenance spine. Labels, markers, routes and scale
  figures toggle independently.
- **Go to** — teleport to any of the 16 spawn points.
- **Layout** — save to / restore from this browser, reset to the layout
  committed in the repository, export/import/copy facility JSON, export a
  greybox GLB.

## Architecture

```
src/
  core/        app loop, renderer, scene layers
  facility/    schema, zone plan, per-zone layout data, validation
  build/       schema entity -> merged geometry + colliders; labels; materials
  nav/         walk, fly, map controllers; the collision model
  input/       shared input state; desktop keyboard/mouse; touch
  editor/      selection and data transforms
  io/          localStorage, JSON import/export, GLB export
  ui/          HUD, editor panel, data panel
  tools/       headless validator entry point
```

The facility is **data, not code**. `src/facility/data/*.ts` contains plain
JSON-serialisable objects conforming to `src/facility/schema.ts`; the builders
in `src/build/` turn those into geometry. Exporting JSON from the menu gives
you exactly that document, so a layout can be hand-edited, diffed, generated by
another agent, or translated into the production engine later.

Collision is analytic: every builder emits Y-rotated boxes, ground height is a
box-top query and blocking is a circle-versus-box push-out. Ramps and stairs
are diced into short steps so slopes need no special case. Nothing walks on a
mesh raycast, which is what keeps it cheap on a phone.

## Deployment

`.github/workflows/prototype-pages.yml` builds this directory and publishes it
to GitHub Pages on pushes to the default branch. It is inert until someone
enables Pages for the repository (Settings → Pages → Source: **GitHub
Actions**) — the workflow cannot and does not change that setting itself.

## Scope

Kept deliberately out: decorative props, pipe spaghetti, crates everywhere,
photoreal materials, post-processing, particles, per-room lighting work. If an
object does not help evaluate the layout, it is not here.
