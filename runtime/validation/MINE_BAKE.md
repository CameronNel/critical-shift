## Refresh and ownership

Blender remains the visual source. The runtime exporter reads the combined builder's already patched mine, then releases other Blender rooms before baking. The mine mesh, mine surface files and bindings change. A separate `MineContext.fbx` supplies UV/material overlays for existing front-end depot meshes visible around the mine; their original mesh assets, transforms and all collision files stay unchanged. Native overlay validation checks bounds and triangle counts before replacing mesh UVs, and does not create duplicate objects. All collision files and other room meshes are SHA-256 checked against the prepared map.

After preparing the existing map and rig with `prepare_player.py` and `prepare_spawn.py`, run from the repository root:

```sh
python runtime/tools/prepare_mine.py --map-ref <committed-assembly-ref> --batched
```

The tool verifies the assembly builder and every staged room/exterior source against the prepared snapshot. If any changed, refresh the assembled delivery with `prepare_spawn.py --map-ref <new-ref> --skip-rig` first, then run `prepare_mine.py` with the same ref. A source geometry change requires refreshing collision and lighting; this material-only operation never reuses collision from changed geometry. General automatic room-by-room geometry refresh is still separate work.

No existing asset metadata is reset. Mine PNG import specifies linear numeric maps, sRGB albedo, atlas padding/filtering and retained alpha. The 4096-pixel resolution and 16-bit baked PNG data are retained. The normal-background repair below changes only exactly black, uncovered RGB texels in current derivative normal atlases. Native runtime copies use high-quality BC7 for colour/metallic/smoothness and BC5 for normals, retaining resolution while bounding loaded texture memory. Emission stays HDR. Unity imports only channels that the materials actually use. This includes spawn: constant emission and direct screen images do not load an unused emission atlas. Unused channels retain their full source files but use a 32-pixel Unity placeholder import. Spawn normal and metallic/smoothness runtime maps also use BC5/BC7 at their original resolution; spawn colour textures retain their existing format. Thin visor reflection-mask maps remain required even when metallic and roughness are constant. Reflection probes require specular convolution, mipmaps, trilinear filtering and clamp wrapping.

## Native scene and lighting

The same isolated `AssembledMap.unity` contains all assembled rooms and existing spawn gameplay. Room inventory follows the manifest, so later assembly additions are validated individually rather than rejected by a fixed six-room count. Spawn remains required, along with the other five existing rooms.

Use the pinned Unity 6000.4.3f1 editor with graphics enabled:

```sh
Unity -batchmode -force-glcore -quit -projectPath runtime/unity \
  -executeMethod CriticalShift.Player.Editor.SpawnVisualReview.BakeAndRender \
  -csCapturePath <absolute-spawn-capture-directory> -logFile <absolute-log>
Unity -batchmode -force-glcore -quit -projectPath runtime/unity \
  -executeMethod CriticalShift.Player.Editor.SpawnVisualReview.Render \
  -csRoom mine -csCameraFile <absolute-mine-cameras-json> \
  -csCapturePath <absolute-mine-capture-directory> -logFile <absolute-log>
```

Unity owns its lightmaps, probes and engine lighting. Mine delivery maps contain source shader inputs, including authored shader AO, rather than baked scene illumination. The default path bakes original objects directly. The optional `--batched` path joins only compatible attribute/UV schemas, captures original material coordinates, and hides the original meshes while their temporary replacements bake. This avoids evaluating duplicated geometry and retains per-object data. Materials that depend on Object Info fall back to direct baking. Constant channels use their exact per-material definitions; unused atlas channels skip scene evaluation. Future completed full atlas passes emit `source-recipe-v2` cache records. Reuse requires matching room/exterior source pins, resolution, texture hashes, the exact generated Blender snapshot, Blender version, batching mode and hashes of the exporter, UV, volume and join tools. The tool rejects changes during export. Context-only refresh cannot certify inherited core atlases as a new full cache. Blender persistent data bounds repeated scene compilation. The assembly's dusk lighting and display transform are read from Blender. The player retains spawn's display transform inside its collision bounds and uses the assembly transform outside them.

Blender's surface UVs and geometry stay untouched. The Blender exporter generates a dedicated per-mesh lightmap UV channel with padding, and a Unity import postprocessor checks its range and coverage. Unity's dense-mesh unwrap was superseded after a 38-minute import; the dedicated export avoids that repeated cost. Larger surfaces receive the normal lightmap budget; props smaller than 0.5 m use baked probes and are excluded from lightmap contribution. Split mine flame/bulb surfaces also use probes: their authored point lights provide illumination, rather than forcing tiny emissive faces into a lightmap. Native validation rejects omitted lightmapped surfaces and incorrect emitter contribution flags. The selected depot overlays participate in the same lighting bake; other front-end preview renderers are muted during the bake and restored afterwards. A native bake returning without lightmaps is rejected, including Unity failures that incorrectly return success. For the bake only, static collision instances are released to bound memory and then restored from their unchanged manifest assets before captures or scene saving.

Join validation exports nine ray expectations from Blender geometry. The centre rail is occupied by the authored ore cart at 0.6 m; both side walking lanes are clear at 0.6, 1.7 and 3.0 m. Unity must match the source contacts and all six clear walking rays. The initial all-clear centreline assumption failed and was corrected after tracing the actual cart; no collider faces or map objects were removed. Each room's display transform has its own Unity material, so the mine cannot overwrite spawn's colour profile.

## Evidence and limits

The task record and inspected images belong in `mine-bake-20261011/`. Technical import, native physical validation, visual comparison and independent art acceptance are separate claims. Do not infer target-hardware performance from this software-rendered container.

The source's two volume containers are hidden as opaque meshes. Blender samples their procedural density through its own shader evaluator into 128×16×16 grids. Unity uses these fields for a depth-aware local atmosphere pass, before the display transform, with illumination sampled from its baked probes. This is an approximation of volume scattering, rather than Cycles' full multiple scattering. Crystal facing color and refractive water also need visual comparison. Neighboring rooms without explicit baked surface packages retain preview materials. Baking the mine does not approve or finish the rest of the facility.

## Timber detail correction

The owner rejected the smeared shed timber. Its boards received approximately 24 atlas pixels per metre: bevel charts and packing left the boards only a few pixels wide. Increasing or softening the lights could not recover the lost grain. The corrected exporter preserves the original packed 1024-pixel wood diffuse and tangent-normal images and their authored UVs in mesh UV2. Repeating images retain their source scale, repeat wrapping and anisotropic filtering. No Blender source image or room is rewritten.

For this source material family, colour is affine in the authored clamped greyscale grain signal. The exporter validates that graph, bakes its two spatial colour coefficients at grain values zero and one, and Unity reconstructs the colour using the original image. The source clamp reaches two, so reconstruction must allow extrapolation above one. Weathering, paint, attributes and source shader AO remain in the coefficient maps. Those two maps use 16 samples to reduce stochastic AO blotches. Normal detail uses the original UV tangent frame and the source normal/bump parameters. Unsupported nonlinear graphs fail export rather than silently using this adapter.

An old flattened atlas is never accepted as a coefficient map. Cache reuse for these maps requires `woodHigh` and the matching `woodRecipe`. Prepared-scene and native material checks also verify the coefficient image, both original images and their bindings. Small Blender/Unity material-only previews show retained grain, but they do not establish final mine lighting or independent art acceptance. Full-room preparation, lighting, matched views and current Player validation remain required.

The rejected final9 wood correction began before that stronger cache schema was introduced. It reused known unchanged legacy atlases and freshly exported wood coefficients; that historical run is recorded as legacy reuse, rather than retroactively certified under `source-recipe-v2`. The final10 corrective iteration completed a fresh rebuild of all nine core/context atlas groups without reuse. Its `source-recipe-v2` record, 70 delivered files, preserved sources and room/collision meshes were independently revalidated before native lighting; records are in `fresh-export-final10/`. Final exported UVs, all delivered texture hashes, geometry preservation and current native evidence remain required. The initial screen-gradient bump approximation failed a controlled native comparison: differentiating the sampled grain produced pixel speckle. The corrected adapter carries Blender's positive, finite `Filter Width` and re-evaluates height at its finite offsets while retaining the original texture gradients. Four source-derived perturbed normals are averaged within each pixel footprint to reduce shading alias that geometry MSAA cannot resolve; this added sampling cost has not been profiled on representative hardware. Controlled normal-only and bump-only references isolate this calculation; final native comparison remains required.

## Empty normal-atlas correction

The mine normal targets previously began as black images. Uncovered texels therefore decoded to an invalid tangent normal and could contaminate chart edges and mipmaps. Future mine normal passes initialize neutral `(0.5, 0.5, 1)` and replace any remaining exactly black RGB texels before saving. The current derivative core atlases receive the equivalent 16-bit correction, with reread verification that every other texel and all alpha values remain identical. Packed authored normal images remain unchanged. This establishes the data correction; fresh native debris and edge comparisons must establish the visible result.

## Fog colour-space correction

A native GPU probe into a linear floating-point render target confirmed that `Material.SetColor` does not decode gamma values for undeclared raw shader uniforms. The previous fog path converted Blender linear colour to gamma and delivered those brighter numbers unchanged to `_Scatter`. The corrected fog path retains Blender linear colour and binds it explicitly with `SetVector`. Actual Unity `Color` properties on lights, the ambient environment and reflection backgrounds retain their required colour conversion. The probe compares raw gamma, declared colour, raw linear-vector and raw linear-colour cases; it does not certify the final fog appearance.

## Corrections after the strict final9 rejection

The full final9 images were rejected. They showed pale shed boards, a green cliff, low floor detail, black timber pixels and dark debris patches. Technical test passes did not establish visual acceptance. Controlled evidence for the next iteration is in `mine-bake-20261011/correction-controls-final10/`; fresh final10 images, regression and Player evidence are still pending.

The timber black pixels were nonfinite RGB in native HDR output, hidden by conversion to 8-bit PNG. The production coefficient atlas produced 383 invalid pixels in the portal control under globally forced anisotropic filtering. Changing compression, bump strength, normal strength or reflection probes did not fix it. Disabling anisotropy on the BC7 `woodHigh` coefficient atlas alone produced zero invalid pixels in all three native camera controls; original diffuse and normal grain textures retain anisotropy 8 and their source UVs. The production shader is unchanged. Mine captures now retain a full-resolution pre-display-LUT HDR EXR, its SHA, camera, graphics driver and prepared-scene proof, and fail if any RGB pixel is NaN or infinite.

The floor shared an atlas with other ground surfaces and received only about 7.25 pixels per metre. It now receives its own 4096 atlas and a continuous temporary UV proxy. The production density calculation measures 76.8568 pixels per metre; export rejects less than 64. This is an area-weighted density guard, not a substitute for visual review or a proof that UV charts never overlap.

The imported combined SUN used Blender irradiance as Unity intensity, despite Unity's built-in diffuse BRDF omitting the division by pi. A source 18% grey plane with SUN energy 1.6 measured approximately 0.0916 linear RGB in Cycles; Unity intensity 1.6 produced 0.288. Native realtime and native baked lighting at 1.6/pi both produce approximately 0.09167. Combined and authored SUN lights now use that measured conversion. The front-end FE_MOON was also incorrectly represented by a legacy point-light record. The mine context now exports its actual source SUN orientation, colour, energy and angular size, and the native scene creates the directional light while suppressing the legacy SUN-as-point record. These directional lights affect the assembled scene, so all three spawn views require a fresh regression review.

The visible front-end cliff is the backface of the authored source geometry. Its native backface lightmap picked up green indirect lighting even with neutral albedo. The scoped context adapter disables received lightmap/probe/reflection lighting on that cliff while retaining its ContributeGI flag, casts, mesh, materials and collisions. This deliberately sacrifices received indirect light there; native persistence and the final grey-cliff image must be reviewed after the fresh bake. No canonical Blender normals or assembly files are changed.

## Imported thermos binding correction

The strict reviewer found that Editor prefab restrictions rejected reparenting the actual thermos visual out of the spawned FBX instance. Its physics/interaction root was created, but the visible model stayed in the locker; existing synthetic carry tests did not detect this. Scene generation now unpacks only the spawn model instance before extracting dynamic children, leaving the FBX/source unchanged. Extraction fails if parenting or the original world pose/scale changes. Its collider now uses aggregate renderer world bounds on the world-aligned runtime root, rather than misreading the rotated FBX local bounds as world-aligned dimensions. A new imported-scene PlayMode test exercises both authored thermoses through pickup, worker motion, sideboard placement, taking back, dropping and a physics tick while checking every child mesh, renderer and material. Its native preflight and subsequent full-suite results must be recorded before acceptance.

The first final10 native lighting attempt was deliberately cancelled after this finding, before completing lightmaps. Its exit 137 records the intentional stop, not another memory-limit failure; logs and memory-event counters are retained under `fresh-export-final10/interrupted-thermos-binding/`. Test-fixture failures are retained separately: the first assumed a mesh on the transform-only thermos root; the second attempted pickup with a carry anchor blocked by the locker. Further attempts retained their collision failures. The revised test checks the actual child meshes and their collider alignment in the common carry-root frame (avoiding legitimate render/physics interpolation lag), stands 2m back for the existing 1.1m carry anchor, and uses separate drop locations for the two thermoses while retaining collision geometry, clearance margins, exclusions and host custody authority.

The real-scene test also exposed a blocked sideboard placement. The original sphere clearance was overly conservative for an upright thermos. Native diagnostics then showed that the old anchor was also physically occupied by the authored `COZY_B_photo`; merely correcting the query shape did not fix that source obstruction. `LocalShiftHost` now queries a carry-root `BoxCollider` with an oriented overlap box at the actual future rotation for pickup/take, placement and drop/lost-lease release. Other or child collider shapes retain the conservative sphere. Buffer-capacity rejection, source anchor height, obstacle/self/worker exclusions and host custody authority remain intact. Scene generation now selects the nearest clear slot on the same authored sideboard, preserving its original placement height. It requires the thermos footprint and clearance box to fit, plus five downward support rays at the centre and footprint corners; insufficient support or no clear slot fails generation. The source photo, tabletop and collision meshes remain unchanged. The final native preflight generated the slot at (1.151, 0.978, -90.660), then passed pickup, movement, obstruction rejection with preserved custody, clear placement, taking back and dropping for both thermoses. The obstruction check separately verifies interaction reach, so ray occlusion cannot falsely pass it. Full current-suite, fresh lighting, visual and Player evidence remain required.
